# Building the Android app (.apk)

This is the part I genuinely can't do from a sandboxed environment — it
needs the real Android SDK, Gradle, and a signing key that should be
yours, not generated by me. Here's exactly what's already done and
exactly what's left, in order.

## What's already done
- Capacitor is installed and configured (`capacitor.config.ts`).
- The native Android project exists at `android/` — a real Android
  Studio project, not a stub.
- Your logo is wired in as the launcher icon (all densities, adaptive +
  legacy) and the splash screen.
- Camera permission is declared and requested at runtime (needed for the
  Snap & Go scan feature to work at all inside the native app).
- Push notification plumbing is wired (device registration, token
  storage, server-side sender) — see `PUSH_NOTIFICATIONS.md` for the
  Firebase setup that's still needed for it to actually deliver anything.
- Offline queueing for Sales is wired (Stock-In can get the same
  treatment on request — ask if you want it added).

## Step 1 — Deploy the web app first
The Android app's WebView loads your app from a **real deployed URL**,
not bundled local files (this app has server-side API routes, so it
can't be a static export). If you haven't deployed yet:
1. Push this project to GitHub.
2. Deploy it on Vercel (or similar) — it's a standard Next.js app, no
   special config needed beyond your existing environment variables
   (Supabase keys, Gemini key, Firebase keys once you've done
   `PUSH_NOTIFICATIONS.md`).
3. Note the deployed URL (e.g. `https://profitsnap.vercel.app`).

## Step 2 — Point Capacitor at your real URL
Open `capacitor.config.ts` and replace the placeholder:
```ts
server: {
  url: 'https://YOUR-REAL-DEPLOYED-URL.vercel.app',
  cleartext: false,
},
```
Then run:
```bash
npx cap sync android
```
This copies the updated config into the native project.

## Step 3 — Install Android Studio
Download from https://developer.android.com/studio (free). This gives
you the Android SDK, an emulator, and everything needed to build —
there's no separate SDK install required, Android Studio bundles it.

## Step 4 — Open and build
1. Open Android Studio → **Open** → select the `android/` folder inside
   this project (not the project root — the `android` subfolder).
2. Let it finish syncing Gradle the first time (few minutes, downloads
   dependencies).
3. **Build → Generate Signed Bundle / APK** → choose **APK**.
4. First time: click **Create new...** to generate a signing key.
   - **Save this keystore file and its passwords somewhere safe and
     permanent** — losing it means you can never publish an update to
     an app already on the Play Store under the same listing, you'd have
     to start over as a new app.
5. Choose **release** build variant, finish the wizard.
6. Android Studio will show a notification when it's done — click
   **locate** to find the `.apk` file (typically
   `android/app/release/app-release.apk`).

## Step 5 — Test it
Install the APK on a real Android phone (easiest: email it to yourself,
or use `adb install app-release.apk` with the phone connected via USB
with developer mode + USB debugging on). Test the camera permission
prompt and a real scan before doing anything else — that's the feature
most likely to need adjustment on a real device vs. the browser.

## If you want it on the Play Store
Building the APK above is enough for direct installs (sharing the file,
sideloading). For a real Play Store listing you'd also need:
- A Google Play Developer account ($25 one-time fee).
- To build an **.aab** (Android App Bundle) instead of/alongside the
  .apk — same wizard in Step 4, just choose **Android App Bundle**.
- Store listing assets (screenshots, description, privacy policy URL —
  you already have `/privacy` and `/terms` pages in this app you can
  point to).

None of that is code work — it's account/store setup, same category as
the Firebase steps in `PUSH_NOTIFICATIONS.md`.
